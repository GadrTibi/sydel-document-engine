# Contribuer au dépôt

## Règles simples

- une PR = un sujet principal ;
- pas de mélange infra + wording juridique + plusieurs documents métier ;
- toute PR doit mentionner le ticket ou l'ADR concerné ;
- toute évolution sur un document doit renvoyer à sa spec.

## Nommage de branches

- `docs/...`
- `chore/...`
- `feat/...`
- `fix/...`

Exemples :

- `docs/bootstrap-github-codex`
- `feat/doc-001-generator`
- `fix/address-composer`

## Checklist minimale avant merge

- tests passants ;
- lint passant ;
- hypothèses documentées ;
- wording juridique revu si concerné ;
- pilotage et spec mis à jour si le périmètre l'exige.
